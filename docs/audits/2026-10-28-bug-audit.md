# Portfoliarr bug audit — 2026-10-28

Status: **review requested; findings only, no application fixes in this PR**.

Companion: [remediation plan](../plans/2026-10-28-audit-remediation.md).

## Scope and evidence

The read-only audit examined the Flask API, SQLite schema and migrations,
market-data and performance calculations, browser JavaScript, Docker startup,
and Android integration source. It used commit
[`a6870a0`](https://github.com/ChristopheAwad/portfoliarr/commit/a6870a03bdcbfb999aeeb5805b07456c300570fc)
as its reproducible code baseline. The full Python/JavaScript-backed suite
passed **1,493 tests** after the optional JavaScript engine was installed.
All custom probes below used temporary SQLite databases and synthetic Yahoo
responses, never real accounts or market data. `node --check` passed on the
browser JS files. A Bandit scan additionally identified the development
debugger/all-interfaces binding.

Since that audit, `main` advanced to
[`85ff828`](https://github.com/ChristopheAwad/portfoliarr/commit/85ff82802ff4f3b139b878ef2932684686c80434),
which changes the 1M view to hourly data. The changed files do not remediate
the issues below; the timezone finding now also applies to the 1M view. Exact
line links below target the original audited commit so they remain stable.

The labels distinguish **confirmed defects**, **conditional exposure**, and
**product-definition decisions**. Severity is proposed for review, not a
claim that a real attacker exploited the application.

## Findings

### AUD-01 — Replayed imports duplicate ledger facts (P1; confirmed)

- Source: [`app.py` preview/duplicate marking and commit](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L4412-L4567).
- Reproduction: POST the same valid one-line paste to
  `/api/transactions/import/commit` twice, using a valid signed-in test
  session and a fake CAD quote. Both responses say `imported: 1`; two
  identical rows are stored.
- Mechanism: duplicate detection is a *preview warning*; the commit path
  never recognizes retry/replay identity. A lost response after a successful
  write can trigger a double import, while the caller cannot tell whether
  the first request committed.
- Impact: overstated holdings/cost and corrupted portfolio performance.
- Distinction: two legitimate, separately submitted trades may have identical
  fields. The fix must make *request retries* idempotent, not globally forbid
  identical trades.

### AUD-02 — Missing ticker history creates a misleading partial chart (P1; confirmed)

- Source: [`app.py` history loading and value/cost folding](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L1585-L1883).
- Reproduction: BUY one AAPL share at CAD 100 and one MSFT share at CAD 200.
  Supply flat AAPL daily history at 100 and make MSFT history raise a timeout.
  The history API returns `200` with `values: [100, 100]` and
  `costs: [300, 300]`, without a missing-ticker marker in the JSON.
- Mechanism: unavailable history contributes zero to the value line while
  every transaction's cost remains in the cost line.
- Impact: a temporary upstream gap can look like a CAD 200 portfolio loss.
  A complete absence of history instead produces an empty chart; the
  dangerous case is a *partial* failure.
- Distinction: the current code comments intentionally preserve paid costs.
  That fact is valid, but a partial value line must not masquerade as a
  complete valuation.

### AUD-03 — Ordinary users have account-administration privileges (P1; policy conflict)

- Source: [`app.py` signup toggle, create user and delete user](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L748-L853).
- Current behavior: every authenticated account can create accounts, delete
  another account with all of its data (given the visible username), and
  enable open registration. This was an explicit trusted-LAN design choice.
- **Owner's clarified requirement (2026-10-28): the first account created
  during setup is the owner; all subsequent accounts are regular users and
  must not have administrative access.**
- Impact: an ordinary invited user can destroy another user's records or
  change the site's registration policy. This is now a requirements defect,
  not merely an optional hardening suggestion.

### AUD-04 — Dev startup exposes Flask debugger on all interfaces (P2; conditional)

- Source: [`app.py` main](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L5190-L5203).
- Running `python app.py` enables `debug=True` on `0.0.0.0`; Bandit flagged
  both. The production Gunicorn Docker command does **not** take this path.
- Impact: unnecessary remote debugger exposure if dev mode is run on an
  accessible network.

### AUD-05 — Legacy session can survive password rotation (P2; confirmed)

- Source: [`app.py` session-version handling](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L432-L452).
- Reproduction: create an authenticated session with `user_id` but no `pv`
  (the pre-version cookie shape); increment the account's password version;
  request `/api/users`. The response is still `200` and the old session is
  stamped with the new version.
- Impact: a dormant legacy session can survive a password change that was
  supposed to invalidate other sessions. New sessions carrying `pv` are
  properly checked; the defect is limited to old-cookie compatibility.

### AUD-06 — Finite inputs can produce invalid JSON arithmetic (P2; confirmed edge case)

- Source: [`app.py` transaction validation](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L3442-L3505)
  and [summary math](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L2120-L2178).
- Reproduction: POST a valid CAD BUY with `price: 1e308` and `qty: 1e308`.
  Both inputs pass the finite-number check and the API returns `201`.
  A later summary returns HTTP `200` with `Infinity` and `NaN` fields;
  browser `JSON.parse` rejects them.
- Impact: malformed but accepted values can persistently disrupt a user's
  dashboard. This is an extreme-input issue, not a plausible normal trade.

### AUD-07 — Cross-exchange intraday labels collapse distinct instants (P2; confirmed)

- Source: [`market_data.py` history label conversion](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/market_data.py#L1222-L1234).
- Reproduction: feed `get_history` a 9:30 a.m. New York bar and a 9:30 a.m.
  Tokyo bar on the same calendar date. Both yield the identical key
  `YYYY-MM-DD 09:30`, although the underlying UTC times are 13 hours apart.
- Impact: the portfolio history union can treat asynchronous markets as
  simultaneous. Affects 1D/5D and, after `85ff828`, hourly 1M.

### AUD-08 — CAD daily/performance return omits FX movement (decision required)

- Source: [`app.py` summary day gain](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L2120-L2130)
  and [historical current-rate conversion](https://github.com/ChristopheAwad/portfoliarr/blob/a6870a03bdcbfb999aeeb5805b07456c300570fc/app.py#L1645-L1691).
- Example: one USD 100 share is unchanged in USD; USD/CAD moves 1.35 → 1.40.
  The holding gains CAD 5 in value, but displayed CAD day gain is zero.
  Historical CAD values also use a flat *current* FX rate, omitting FX
  changes from the time-weighted performance chart.
- The formulas are documented as deliberate, so this is not presented as
  an accidental regression. The owner/reviewer must decide whether
  **"CAD performance" means actual CAD return including FX** or
  **security-only return with FX intentionally excluded**. Labels, tests,
  and implementation should then agree with that definition.

## Exclusions / limits

- No live production server or real ledger was accessed.
- No live Yahoo accuracy/reliability characterization or device-level
  Android instrumentation was performed. Android source and test contracts
  were inspected; native Android JVM/device tests were not run here.
- Planned dividend and split support, foreign-currency breadth beyond
  USD/CAD, and portfolio accounting-definition changes beyond AUD-08 are
  *not* silently added to this remediation's scope.
- Passing existing tests does not invalidate the reproductions above: their
  particular failure modes were not protected by the existing suite.

## Handoff

This document is evidence and prioritization, not authorization to deploy
fixes. Implement the companion plan in separately reviewable phases, with
regression tests written before risky migrations or ledger mutations.
