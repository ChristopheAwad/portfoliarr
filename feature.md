# #3 Transaction Fees: implementation plan

## Status and intent

Implemented after user approval. The full `python -m pytest` suite passes (921 tests). The user approved the browser GUI and requested PR #79. This feature adds a per-transaction fee to the ledger so costs, realized gains, and reported returns include what a trade actually cost. Old transactions remain valid. The fee is a stored transaction fact, not a live market value.

## Contract to implement

- `fee` is one non-negative, finite amount in the transaction's **native currency**, for the entire trade, not per share. It is independent of `price` and `qty`. An absent or JSON `null` fee means no recorded fee and contributes zero to calculations. Keep that absence as SQL `NULL`; preserve an explicit numeric `0` as `0`. Do not invent historical fees during migration.
- A BUY costs `price * qty + fee`; a SELL returns `price * qty - fee`. CAD computations convert the full transaction amount at **that transaction's stored FX rate**; legacy USD rows without a stored rate use the existing live-rate fallback only where that endpoint already permits it. Native ledger display uses the native amount. Fees never alter shares, quotes, daily price movement, or allocation weights.
- POST accepts optional `fee` alongside ticker/date/price/qty/type. PUT accepts optional `fee` alongside date/price/qty/type; ticker and currency remain immutable. The shared validator rejects booleans, strings, arrays/objects, negative numbers, and non-finite numbers, but accepts zero, positive decimals, omitted, and null. No invalid request writes a row. PUT still re-derives FX from a corrected date and re-reads its reply from SQLite. GET and POST/PUT replies expose the stored `fee` fact.
- The ledger form gets an optional `Fee` number input, step `any`, minimum `0`. A blank field sends `null`, not `Number("") == 0`. Edit prefills a stored fee and clears it when the row has no fee; reset and quick sell leave it blank. The transaction detail row displays the fee in **native currency with a currency label**, even when the ledger is in CAD mode, so the number is never mislabeled. The group row's Fee cell is blank because the group has no single transaction fee. No new closed-sales column: that table's realized amount already includes fees. Do not disturb transaction price auto-fill or its full-precision backing value.
- The ledger's net cost (`group_cost_basis`), portfolio summary's `cost_basis`, and chart's `costs` add each BUY fee and each SELL fee to the existing signed net-cost sum: `BUY: gross + fee`, `SELL: -(gross - fee)`. The matching total-gain amount and percentage follow that cost. A detail row still compares that trade's original price to today's price; its gain subtracts the fee for either type (`today's value - original gross - fee`) and its percentage divides by `original gross + fee`. This is not the SELL's realized gain; Closed sales computes that separately. Keep day gain/percentage price-only. Group `group_avg_cost` incorporates fees in the current position's average cost per share even when the quote fails. Conversions use the stored transaction rate when available and do not blend native and CAD prices in one group.
- Closed-sales average-cost replay adds BUY fees to long acquisition basis, subtracts SELL fees from long proceeds, subtracts SELL fees from short opening proceeds, and adds BUY fees to short-cover costs. Allocate a crossing transaction's fee **pro rata by shares** between the closed portion and the newly opened opposite-side pool. For partial closes, remove the closed shares at the position's prior average. Native `avg_cost` includes opening fees per share; CAD `avg_cost_fx` remains defined as CAD pool/native pool when a valid nonzero denominator exists, otherwise null. When any needed FX fact is missing or unsupported, keep native facts and existing null/degraded CAD behavior; never substitute 1:1. Keep `FLAT_QTY_TOL` behavior and the rule that short-cover gains appear in `total_realized`, not a sale row. An opening-only SELL still has `realized: 0` when its rate is known; its fee belongs to the short basis until cover.
- The history chart's `values` still show holdings at market price. Its `costs` include fees at the same absorption bar as each transaction. Leave TWR `flows`, `index_values`, and `twrr_pct` **price-only**: the current no-cash TWR view removes gross trade flows and cannot show fees as an investment return without a cash account. Document this distinction in a durable code comment or `project-brief.md`, and do not let a fee silently distort the existing TWR calculation.
- The paste-import format remains four tab-separated columns with no fee column. Preview and commit continue to reparse original text; committed imported BUY rows have `fee: null` and the reported row, if returned, uses that value. Preserve the best-effort import behavior and status codes.
